# Local backup and recovery rehearsal

The local ERP state lives in `.wrangler/state`. The daily user timer runs at **02:30 Asia/Kolkata**, including a catch-up run after a missed scheduled time. Its service runs `scripts/backup-local.py --verify`: each SQLite database is copied through SQLite's backup API, other state files are copied, hashes and database metadata are recorded, and `scripts/verify-backup.py` rehearses a restore in a new temporary directory. The rehearsal checks every file hash, SQLite integrity, schema, and table counts. It never writes to the active `.wrangler/state` directory.

The timer is `erp-local-backup.timer`. Check it with `systemctl --user list-timers erp-local-backup.timer` and `systemctl --user status erp-local-backup.timer`. Check the latest completed backup and rehearsal result in `outputs/backups/latest-status.json`; failures are recorded there and in `systemctl --user status erp-local-backup.service` or `journalctl --user -u erp-local-backup.service`. An abrupt process termination may leave the preceding status, so check its timestamp and the timer's service result. Run `python3 scripts/backup-local.py --verify` for a fresh backup and rehearsal, or `python3 scripts/verify-backup.py outputs/backups/<snapshot>` to check an existing snapshot. The installer is `bash scripts/install-backup-timer.sh`.

Backups contain business records, uploaded files, and account data. The backup script creates new snapshots and files with owner-only permissions. Existing snapshots were made owner-only on 10 October 2026. The script never prunes or overwrites snapshots. Monitor disk space and set an approved retention policy before deleting any copy. SQLite databases are individually consistent; simultaneous changes across separate databases and loose files are not captured as one global transaction. Schedule a quiet period or stop writes when an exact cross-store point-in-time snapshot is required.

Preserve it as evidence, but use a newly verified snapshot for recovery. A test run through the installed service produced `20261010-075533-af556f57` and checked the same inventory in 0.130 seconds.

For a recovery drill, run the verifier on the intended snapshot and inspect its JSON summary. For a real recovery, first stop the ERP and other processes writing to `.wrangler/state`, save the current state as a separate backup, and restore the selected snapshot's `state/` tree into a **new** directory. Verify the new directory and switch the service's state location only after a controlled maintenance review. Do not copy a snapshot over a running `.wrangler/state` tree.
